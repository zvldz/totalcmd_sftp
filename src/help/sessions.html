Session Management

The plugin provides comprehensive session management for storing and organizing connection configurations.

Saved Sessions

Creating a Session

  1. Open connection dialog (Ctrl+F1)
  2. Enter connection settings (host, username, authentication, etc.)
  3. Press F7 or click in session field
  4. Enter session name in the dialog (Total Commander shows "New folder" - this is expected)
  5. Settings are automatically saved under that name

Editing a Session

  1. Select session from dropdown
  2. Press Alt+Enter
  3. Modify settings as needed
  4. Changes are saved automatically

Deleting a Session

  • Select session from dropdown
  • Press F8 or Delete
  • Confirm deletion

Organising Sessions in Folders

Saved sessions can be grouped into folders for easier navigation when you accumulate many of them. Folders are implicit: they exist as long as at least one session lives under them, and disappear when the last one is removed. There is no separate "create empty folder" step.

Putting Sessions into a Folder

  • From scratch: press F7 inside an existing folder — the new session is created in that folder automatically (folder name is taken from the current path).
  • Move an existing session: press F6 on the session and type a new path that includes a folder, e.g. \work\web1. The folder appears in the listing on the next refresh.
  • Manually: save a session whose Display Name uses / as a hierarchy separator (e.g. work/web1). The plugin splits on / when building the listing.

Renaming or Moving a Folder

Press F6 on a folder entry to rename it. All sessions under the folder are renamed in one go — both the INI section names and any jumpsessionref values pointing into the folder are updated, so jump-host references survive the rename.

Deleting a Folder

F8 on a folder removes every session in it (recursively). Total Commander shows its standard "delete non-empty folder?" confirmation first. Jump-host references targeting the deleted sessions are cleared so the by-reference picker does not surface them as broken markers.

Copying and Moving with F5 / F6 / Drag-and-Drop

Drag-and-drop and TC's copy/move commands work uniformly across the plugin namespace: dropping a folder onto another folder relocates every session inside. Behind the scenes this is the same code path as F6, so jump-host references are kept consistent.

Session Storage

Storage Location

  • Sessions stored in sftpplug.ini
  • Located in Total Commander configuration directory
  • Typically: %APPDATA%\GHISLER\ or TC installation directory

Stored Information

  • Hostname and port
  • Username
  • Encrypted password (if saved)
  • Transfer mode settings
  • Proxy configuration
  • Codepage/encoding settings
  • Key file paths
  • Advanced options (compression, shell transfer, etc.)
  • LAN Pair role, peer, and timeout
  • Jump Host / ProxyJump settings

Password Security

  • Passwords encrypted with Windows DPAPI
  • Encryption is user-specific (cannot be used by other users)
  • Passwords not stored in plain text
  • Optional: Don't save password, prompt each time

Import Sessions

Sessions from other programs appear in the [Imports] folder in the plugin root, one subfolder per source program. Nothing in the source program is modified.

Supported sources

  • SecureCRT — %APPDATA%\VanDyke\Config\Sessions\
  • PuTTY — HKCU\Software\SimonTatham\PuTTY\Sessions, or a putty.reg export
  • WinSCP — HKCU\Software\Martin Prikryl\WinSCP 2\Sessions, or a portable WinSCP.ini
  • FileZilla — %APPDATA%\FileZilla\sitemanager.xml
  • KiTTY — common install locations, or any Sessions\ folder you point the plugin at

Using an imported session

  • Enter — connect straight away, using the settings read from the source program
  • F5 — copy into your own session list; select several first, or Ctrl+A for all of them
  • [Refresh] inside a source folder — pick up sessions added or renamed in the source program
  • [Add custom location...] — point the plugin at a portable install or a backup folder

Passwords

  • KiTTY and FileZilla passwords are carried over when the source has one saved
  • PuTTY keeps no password on disk; WinSCP and SecureCRT passwords are not imported
  • Imported passwords are re-protected with Windows DPAPI, never stored in plain text

Key File Compatibility

  • Key paths preserved as-is, with environment variables resolved
  • Supports .pem, .ppk, and OpenSSH keys with no extension
  • PPK v2, PPK v3 (Argon2) and ed25519 converted natively — no external puttygen needed

See Import sessions from other programs for full details.

After Import Checklist

  1. Open imported session with Alt+Enter
  2. Verify transfer mode matches server capabilities
  3. Check proxy settings if applicable — proxy definitions are not imported
  4. Verify key file paths are valid
  5. Test connection
  6. Adjust SCP/Shell options for restrictive hosts

Session Organization Tips

Naming Conventions

production-server1      - Clear environment prefix
dev-db-backup           - Purpose in name
clientname-project      - Client/project based
aws-eu-west-web         - Cloud provider + region

Session Groups

Use naming patterns for logical grouping:

  • Sessions appear alphabetically in dropdown
  • Prefix with category for grouping
  • Example: AWS-, Azure-, Local-

Session Limits

  • No hard limit on number of sessions
  • Practical limit: INI file size (typically fine for hundreds)
  • Each session ~500-1000 bytes in INI

Troubleshooting

Session not saved

  • Check INI file is writable
  • Verify Total Commander has write permissions
  • Check disk space

Password not remembered

  • Ensure "Save password" was selected
  • DPAPI requires same Windows user
  • Re-enter password and save again

Import fails

  • Verify source sessions exist in registry (PuTTY/WinSCP) or in the correct folder (Portable/KiTTY)
  • Check registry permissions for registry-based sources
  • For KiTTY Portable: ensure the folder contains a Sessions subdirectory with session files
  • Run Total Commander as administrator if needed
Tip: Export your sftpplug.ini periodically for backup. Sessions are portable between machines (passwords require same Windows user).
