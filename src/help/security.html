Security Model

Transport security

  • SSH connections (SFTP, SCP, Shell fallback, Jump Host) are always encrypted by the SSH protocol.
  • Use HTTPS for all PHP Agent / PHP Shell traffic. Avoid plain HTTP on any network you do not fully control.
  • LAN Pair sessions are authenticated with SPAKE2 and encrypted with AES-256-GCM (PAIR3 protocol) within the local network.

Password and credential storage

Storage modeINI formatDescription
TC Master Passwordpassword=!Delegated to Total Commander's own CryptProc API
DPAPIpassword=dpapi:<base64>Windows CryptProtectData, bound to your Windows user account
Explicit plaintextpassword=plain:<text>Never written to sftpplug.ini; read when typed in by hand. Session files copied out of the plugin carry passwords this way
Legacy XOR<decimal triplets>Read-only; used by very old plugin versions — never written for new sessions
  • The jump host's password is stored the same ways, under its own key jumppassword; in the password manager it is kept as <session>$$jump.
  • A proxy's password is stored the same ways, under proxypassword in the proxy's section; in the password manager it is kept as proxy$$pass (first proxy) or proxyN$$pass.
  • A password that comes into the plugin from elsewhere — a session file dropped onto it, a session copied from [Imports] — goes into the password manager or is not kept. A ! in a session file is ignored.
  • The PHP Agent PSK is stored as a salted SHA-256 hash inside sftp.php — the raw secret is not written to disk on the server.
  • A PuTTY .ppk key is converted for the SSH library in memory only; the decrypted key is never written to disk.

Master password not remembered

Total Commander keeps passwords protected by the master password, and the master password itself, in its own file wcx_ftp.ini, next to wincmd.ini. When Total Commander is installed in Program Files and keeps its settings there too, it may be unable to create that file: the master password then lasts only until Total Commander is closed, and saving a session password with "Protect password with password manager" fails. The plugin reports that and stores the password encrypted in sftpplug.ini instead.

To fix it, create wcx_ftp.ini in the Total Commander folder and give your Windows account write access to it — from an administrator PowerShell:

New-Item "C:\Program Files\Total Commander\wcx_ftp.ini" -ItemType File
icacls "C:\Program Files\Total Commander\wcx_ftp.ini" /grant "${env:USERNAME}:F"

Or let Total Commander keep its settings in %APPDATA%\GHISLER, where it can write.

SSH host identity verification

  • The server's fingerprint is stored in sftpplug.ini on first connection, as SHA256 in the form OpenSSH prints it (SHA256:…), so it can be checked on the server with ssh-keygen -lf. The confirmation shows the MD5 as well. An MD5 stored by an earlier version still matches and is rewritten as SHA256 on that connection, without a prompt.
  • On every subsequent connection the fingerprint is compared. A mismatch raises an explicit warning dialog — you must confirm before connecting.
  • Jump Host (bastion) keeps a separate stored fingerprint from the final target host.
  • Accepting a new fingerprint should always be a deliberate decision.

LAN Pair cryptography

  • The pairing password, the same on both computers, becomes a pair key through PBKDF2-HMAC-SHA256 with 120,000 iterations, salted with the two computers' ids.
  • The computers prove the key to each other with SPAKE2 (RFC 9382, P-256). Neither the password nor the key is transmitted, and a recorded exchange gives nothing to guess the password against offline; an attacker who joins in gets one guess per connection, each costing a second.
  • Everything after the handshake is encrypted and authenticated with AES-256-GCM, with a separate key per direction and numbered frames: an altered, replayed or reordered frame ends the connection.
  • Pairing requires the password. After a successful handshake the key is stored encrypted with Windows DPAPI for your Windows user account, per peer pair, and used for later sessions: other Windows accounts on the machine cannot read it.
  • The LAN Pair ports are opened only when LAN Pair is used (a LAN Pair session or Pair...) and closed with the last LAN Pair session (a Donor serves until Total Commander exits). The TCP ports are bound exclusively. The TrustedInstaller token is taken only after the handshake.
  • Session timeout is enforced between operations; active transfers are never killed mid-stream.
  • The cryptography is OpenSSL (statically linked) and Windows BCrypt — no third-party DLLs.

Plugin error isolation

Every exported plugin function is wrapped by an exception firewall. If an unexpected error occurs inside the plugin:

  • The exception is caught before it can reach Total Commander.
  • The current operation is aborted and an appropriate error code is returned to TC.
  • A diagnostic dialog is shown with the error type and call location.
  • Total Commander continues running normally — a plugin bug cannot crash the host process.

Key file security

  • Private key files (PEM/PPK) are read only at connection time and not stored in the session profile.
  • PPK v2 and v3 are converted to an in-memory PEM form — the conversion result is never written to disk.
  • Argon2 (PPK v3 key derivation) comes from the OpenSSL statically compiled into the plugin — no separate DLL is involved. The Argon2 settings a key file asks for are capped, so a crafted file cannot demand unbounded memory or time.

Debug log

  • Stable releases write no debug log.
  • Test (rc/beta) builds write a debug log to %TEMP%\sftpplug.log, in the Windows user's own temporary folder.
  • Quote commands, the SFTP server command and SCP commands are not written to the log. Remove host names, user names and paths before sharing it.

Operational recommendations

  • Keep "Protect password with password manager" (default) ticked, or use DPAPI storage — never plain text — for all sessions.
  • Restrict access to the TC directory containing sftpplug.ini — it holds encrypted credentials.
  • Restrict URL exposure for PHP Agent deployments; use HTTPS with a valid certificate.
  • Rotate SSH keys and PHP Agent passwords periodically.
  • Do not commit sftpplug.ini or sftp.php with live credentials to public repositories.
  • Keep the plugin and PHP runtime up to date.
Important: Security depends on TLS configuration, server hardening, and secret management together — not on the plugin alone.
