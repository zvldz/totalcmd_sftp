Shell Fallback (cat/base64)

This plugin includes shell-based transfer strategies for servers where SFTP/SCP are restricted or unreliable.

Why this matters

  • Some hosts allow shell commands but block normal SFTP/SCP channels
  • Some tools (including standard clients) fail there; plugin can continue using shell pipelines
  • Shell fallback can succeed where typical tools often fail

Implemented paths

  • Raw shell transfer: cat stream paths for direct data movement
  • Base64 chunk transfer: Robust fallback for restrictive environments
  • Byte-exact resume: Transfers continue at the exact byte where they stopped (tail -c +N, append)
  • SCP shell mode: SCP protocol over an exec channel (scp -t / scp -f)

Commands used

The plugin uses standard Unix commands:

  • cat - Raw file streaming
  • tail -c - Reading from an offset on resume
  • base64 - Encoding for text-only channels
  • ls, mkdir, rm, rmdir, mv, cp, chmod - File operations
  • stat - File metadata

When to enable

  • Enable Use shell transfer (for blocked hosts) when SCP/SFTP fail due to host policy
  • Use together with SCP settings depending on host behavior
  • For maximum force behavior, use shell transfer force workflow
  • SFTP subsystem unavailable errors
  • SCP permission or protocol errors

Transfer methods

Method 1: Raw cat

Download: cat '/remote/file.txt'          (resume: tail -c +N '/remote/file.txt')
Upload:   cat > '/remote/file.txt'        (resume: cat >> '/remote/file.txt')

Fast, no encoding overhead. Used for resumed transfers on SCP-only sessions; a failure or a size mismatch switches to base64.

Method 2: Base64 encoding

Download: base64 '/remote/file.txt' | fold -w 76
Upload:   printf '%s' '<chunk>' | base64 -d >> '/remote/file.txt'

Most robust - works through any text-only channel. 33% size overhead. With Use shell transfer enabled, every transfer uses this method over the hidden shell.

Performance considerations

  • Raw cat: Fastest, no overhead
  • Base64: 33% size increase, encoding/decoding CPU cost
  • The raw path falls back to base64 automatically when it fails

Security notes

  • Filenames single-quoted for the shell
  • A name with a control character is not sent to the interactive shell
  • Commands executed within user's permission scope
Note: Shell fallback prioritizes compatibility over terminal semantics. Some interactive features may not work.
