Transfer Resume

The plugin supports resuming interrupted transfers in SFTP mode and in Shell Fallback mode. Resume behavior differs depending on the active transfer method.

Text mode

When a file is transferred in text mode (line-break conversion), the byte offsets on both sides differ, so the file is never continued: a resume becomes a full transfer from the start.

SFTP (primary mode) — full resume support

SFTP resume works for both downloads and uploads.

Download resume

  1. Total Commander detects that a partial local file already exists at the destination.
  2. TC passes a resume flag to the plugin.
  3. The plugin takes the size of the local partial file. A local file already as large as the remote one is not continued (equal size counts as done).
  4. The remote file handle is seeked to the end of the already-downloaded portion.
  5. Transfer continues from that offset.

Upload resume

  1. TC detects a partial remote file.
  2. The plugin opens the remote file without truncation and queries its size via SFTP fstat.
  3. Upload continues from the local file offset matching the remote file size.
Note: Resume requires that the remote file is the beginning of the local one. If the server does not report the remote size, or the remote file is larger than the local file, the upload is refused with a write error instead of overwriting the remote file.

SCP (native) — no mid-transfer resume

The SCP protocol does not support seeking into a remote file. When you resume a transfer on a session that uses SCP for data:

  • With SFTP available, that file is transferred over SFTP instead, with SFTP resume.
  • On an SCP-only session, the resume goes through Shell Fallback (see below).
  • An interrupted SCP transfer that is not resumed restarts from the beginning.

Shell Fallback — byte-exact resume

Shell fallback continues a file at the exact byte where it stopped.

  • Download: the remote side reads from the offset with tail -c +N (raw, or piped through base64), and the data is appended to the local partial file.
  • Upload: the plugin reads the remote size with wc -c and appends from that offset. Each base64 chunk is encoded and decoded on its own, so no alignment is needed and no bytes are sent twice.
  • An upload resume is refused when the remote size cannot be read or the remote file is larger than the local one.
  • A resumed raw download that ends with the wrong size is reported as a failure.
Performance note: Shell fallback is significantly slower than SFTP or SCP due to base64 encoding overhead and shell command round-trips. Use it only when SFTP and SCP are both unavailable on the server.

PHP Agent — single-file resume

  • Download: the plugin asks the agent for the file from the size of the local partial file on (GET with an offset) and appends to it.
  • Upload: data goes to <file>.part on the server and is renamed into place when complete. On resume, the plugin continues an existing .part from its size; a .part larger than the local file is ignored and the upload starts over. Without a resume request, a leftover .part is never continued.

PHP Agent TAR stream transfers (directory download via TAR_STREAM, batch upload via TAR_EXTRACT) do not support resume. The entire TAR stream must complete in one HTTP request. If a TAR transfer is interrupted, re-copy the whole directory.

LAN Pair — download resume

LAN Pair downloads support resume: the peer sends the file from the size of the local partial file on. If the session times out or the connection drops mid-transfer, you can reconnect and resume using TC's standard resume prompt. Uploads always send the whole file.
