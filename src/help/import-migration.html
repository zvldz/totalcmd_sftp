Import sessions from other programs

The plugin can read the session lists of other SSH and file-transfer programs and show them as ready-to-use entries. Nothing in the source program is modified — the plugin only reads.

The [Imports] folder

Open the plugin in Total Commander. Alongside your own saved sessions you will see a folder named [Imports]. It appears automatically as soon as at least one supported program is detected on the machine, or after you add a portable location by hand.

Inside [Imports] there is one folder per source program:

[Imports]
├── [SecureCRT]
├── [PuTTY]
├── [WinSCP]
├── [FileZilla]
└── [KiTTY]

Only the programs that were actually found are listed.

Inside a source folder

Each source folder holds the sessions found for that program, plus a few command entries:

EntryWhat it does
[Refresh]Re-reads the source program and updates the list. Run this after you add or rename a session in the source program.
[Add custom location...]Point the plugin at a portable installation, a backup folder, or a USB stick in addition to the auto-detected location.
[Manage custom locations]Lists the locations you added. F8 removes one and drops only the sessions that came from it.
A sessionEnter connects. F5 copies it into your own session list.

Two ways to use an imported session

Connect directly (Enter)

Press Enter on a session and the plugin connects using the settings read from the source program. Nothing is written to your own configuration — the entry stays a live view of the other program's session. If you later change the session in PuTTY, hit [Refresh] and the change is picked up.

Make it your own (F5)

Select one or more sessions and press F5 (or drag them) onto the other panel showing the plugin root. They are written into your sftpplug.ini as ordinary saved sessions and from then on behave like any session you created yourself — you can edit them with Alt+Enter, rename with F6, put them in folders.

To copy every session of a source at once, enter its folder, press Ctrl+A (or Num *) and then F5.

F5 onto a real filesystem path writes a portable INI snippet instead, which you can carry to another machine and drop back onto the plugin root.

KiTTY is portable by design and has no fixed install path. If you unpacked it somewhere the probes do not cover — a Downloads folder, a second drive, a USB stick — the source folder stays empty until you add the location through [Add custom location...].

Which sessions appear

Only sessions the plugin can actually open are listed. Entries using a protocol outside SSH/SFTP/SCP are filtered out:

  • SecureCRT — non-SSH2 sessions are skipped.
  • PuTTY / KiTTY — only Protocol=ssh.
  • WinSCP — SFTP and SCP sessions are kept; FTP, WebDAV and S3 are skipped. Saved window layouts (Workspaces) are not sessions and never appear.
  • FileZilla — only SFTP sites; FTP, FTPS, WebDAV and S3 are skipped.

Template rows the source programs keep for their own defaults (Default Settings) are filtered out everywhere.

Folder structure is preserved: a WinSCP session in a folder, a FileZilla site inside a <Folder>, or a SecureCRT session in a subdirectory all show up as nested folders in the panel.

Passwords

Whether a password comes across depends on how the source program stores it, and on whether saving it was a deliberate choice by the user:

  • PuTTY — nothing to import; PuTTY does not keep a password on disk at all.
  • WinSCP and SecureCRT — not imported. You are asked for the password on the first connection, or you can save one through the plugin's own connection dialog.
  • FileZilla — imported when the site uses Save password. Sites protected by a FileZilla master password are skipped and you are prompted instead.
  • KiTTY — imported. Ticking Save password in KiTTY is an explicit action, so the value is carried over.

Whenever a password is imported it is re-protected with Windows DPAPI before being stored, exactly like a password you type into the plugin yourself. Nothing is written in plain text.

Key files

  • Paths are taken over as they are, with %ENVIRONMENT% variables resolved.
  • .ppk keys are converted on the fly — PPK v2, PPK v3 (Argon2) and ed25519 all work, no external puttygen needed.
  • OpenSSH keys are used directly, including files with no extension such as id_rsa or id_ed25519, which FileZilla and KiTTY commonly reference.
  • After importing from a portable installation, check that the key path still points somewhere valid on this machine.

The session list is cached

Session lists are stored next to sftpplug.ini so they are available immediately when Total Commander starts, without re-scanning anything. Consequences worth knowing:

  • Changes you make in the source program become visible after [Refresh], not before.
  • If a source becomes temporarily unreachable — a USB stick unplugged, a network share offline — its sessions stay listed rather than disappearing. They are removed only when the source is reachable and genuinely empty.

Not carried over

Proxy, firewall and tunnel definitions are not imported yet. A session that connects through a proxy in the source program will import cleanly, but the proxy has to be set up again in the plugin. Host key fingerprints are not inherited either — the plugin asks you to confirm the fingerprint on the first connection, as it does for any new host.
