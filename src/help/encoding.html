Character Encoding and Codepages

Two session settings decide how the plugin treats text: the encoding of file names on the server, and the server's line breaks, which text mode transfers use.

File Name Encoding

Set in the session's connection settings:

  • Auto-detect (default): after login the plugin runs echo $LC_ALL $LC_CTYPE $LANG, then locale. A value naming UTF-8 or utf8 (any case, e.g. en_US.utf8) means UTF-8; otherwise the Windows ANSI codepage is used. The result is saved in the session, so the check runs once.
  • A system with no locale variables and no locale command (busybox on a camera or router) is taken as UTF-8.
  • An account that runs no commands at all (SFTP only) uses UTF-8 for that connection; nothing is saved, and the next connection checks again.
  • UTF-8: always UTF-8.
  • A codepage: ANSI (local), ASCII/DOS (OEM), MacOS, Windows 1250–1258, 932 (Japanese), 936 (Simplified Chinese), 949 (Korean), 950 (Traditional Chinese), 874 (Thai), 437 and 850 (DOS), 20866 (KOI8-R).
  • Other (enter manually): asks for a codepage number (e.g. 28591); a number Windows does not know as a codepage keeps the previous one.

Names that are not valid UTF-8

In a UTF-8 session, a name containing bytes that are not valid UTF-8 (written by an older program in another codepage) is shown whole, and every byte is kept: such a file can be opened, renamed, copied and deleted like any other.

Text Mode Transfers

Total Commander's transfer mode (Binary, Text, or Auto with its list of text file patterns) is passed to the plugin. It only has an effect when the session's line breaks are Unix (LF); with Windows (CR/LF) every file is transferred as it is.

  • Binary: bytes are transferred unchanged.
  • Text: download converts LF to CRLF (a CRLF already there stays); upload converts CRLF to LF. A lone CR is left alone.
  • Auto: text mode for files whose name matches Total Commander's text patterns, binary for the rest. The patterns are set in Total Commander, not in the plugin.
  • A file with a NUL byte is binary and is not converted: on download a NUL in the first 64 KB decides, on upload one anywhere in the file.
  • A byte order mark is ordinary data: it is neither added nor removed.
  • A text mode transfer is never resumed: the sizes on both sides differ, so it starts over.

Line break auto-detection

With line breaks on Auto, the plugin runs echo $OSTYPE after login: Linux, Unix or AIX means Unix (LF). Otherwise it looks at the line endings of an ls -l reply. The result is saved in the session.

Unicode in Paths

  • Local paths: Windows UTF-16, including paths over 260 characters
  • Remote paths: UTF-8 or the session's codepage
  • Session names: stored in sftpplug.ini as UTF-8

Common Issues

Garbled file names

  • Auto-detect saved the wrong answer: pick UTF-8 or the right codepage in the session
  • Asian names: UTF-8 if the server uses it, otherwise 932/936/949/950

Text files have wrong line endings

  • Set the session's line breaks to Unix (LF), then choose Text or Auto in Total Commander
  • In Auto mode, check that the file matches Total Commander's text patterns
  • UTF-16 files contain NUL bytes and are always transferred as binary
